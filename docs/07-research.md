# 07. 자료 조사 — 웹 검색과 자료 저장

이 문서는 작가가 사이드 AI 패널에서 하는 자료 조사가 어떤 검색 백엔드로 동작하는지, 조사 결과를 자료로 저장하는 규칙, 저장한 자료를 집필에 쓰는 규칙을 정리한다. 검색 호출은 story 역할(packages/story-engine), 자료 화면은 frontend, 저장은 backend가 맡는다.

## 검색 백엔드

자료 조사는 **Claude의 `web_search`와 `web_fetch` 도구**로 한다. 두 도구는 story-engine의 얇은 인터페이스 뒤에 둔다([04 스토리 엔진의 텍스트 LLM 구성](04-story-engine.md#텍스트-llm-구성)).

- 공급자가 늘지 않고, 인용이 기본으로 돌아오며, 이미 쓰는 SSE 스트리밍 경로를 그대로 쓴다.
- `web_search`는 검색 결과와 인용(URL·제목·150자 이내 인용문)을 돌려주지만 페이지 본문은 암호화되어 읽을 수 없다. 본문 확인이 필요하면 `web_fetch`로 가져온다.
- 대안 검색 API와 가격이 비슷해 별도 공급자를 둘 이점이 작다.

### 조사 근거 (2026-11-01 조사 에이전트 보고, 일부 미검증)

| 선택지 | 가격 | 비고 |
|---|---|---|
| Claude `web_search` | 1천 검색당 $10 + 결과 토큰 | 인용 기본 제공, `allowed_domains`·`blocked_domains`·`max_uses`·`user_location` 옵션(국가 코드 KR 허용 여부 미확인) |
| Claude `web_fetch` | 도구 자체 무료, 토큰만 과금 | 대화에 이미 나온 URL만 가져올 수 있다 |
| Tavily | 1천 기본 검색 약 $8 | 국가 가중치, 원문 텍스트 제공 |
| Brave Search API | 1천 검색 $5 | 결과를 보관하려면 별도 유료 플랜 |

질문 하나당 비용은 검색 2~4회와 결과 토큰을 합쳐 대략 $0.05~0.15로 추정된다(조사 에이전트 추정).

### 빌드 전 검증 — 한국어 검색 품질 비교

한국어 검색 품질은 어느 선택지도 측정된 자료가 없다. 그래서 빌드 전에 **실제 한국어 조사 질문 20~30개**(예: 조선 시대 관직 체계, 1990년대 서울 경찰서 구조, 도검 종류, 의학적 디테일)로 **Claude 검색과 Tavily를 비교**해 점수를 매긴다. Claude 검색이 크게 뒤지면 인터페이스 뒤에서 **Tavily로 교체**한다. 시험 계획은 [08 제작 계획](08-build-plan.md)에 있다.

### 근거 출처 제약 — 네이버

**네이버 블로그, 네이버 뉴스, 네이버 지식백과**는 robots.txt에서 ClaudeBot·Claude-SearchBot을 차단하고 "RAG 목적 봇 접근 금지"를 명시하고 있다(조사 에이전트가 robots.txt를 직접 확인). 따라서 어떤 검색 백엔드를 쓰든 이 출처를 **근거 출처로 쓰지 않는다.** 브라우저 자동화 등으로 우회하지도 않는다. 나무위키와 한국민족문화대백과는 크롤러를 허용한다(조사 기준).

## 자료 저장 규칙

조사 답변은 사이드 패널 대화로만 남고, 작가가 **"자료로 저장"을 누를 때만** 자료가 된다. 버린 조사 결과가 집필 근거에 섞이지 않게 하기 위해서다.

| 저장 항목 | 내용 |
|---|---|
| 제목 | 작가가 알아보기 쉬운 이름 |
| 질문 | 원래 조사 질문 |
| 요약 | AI 초안을 작가가 고칠 수 있다. AI 초안에는 "미검증" 표시를 붙이고, 작가가 확인하면 표시를 뗀다 |
| 출처 | URL · 제목 · **150자 이내 인용문** · 조회 시각, 여러 개 |
| 태그 | 집필 중 언급을 찾는 기준 |

- **웹 페이지 원문은 저장하지 않는다.** 짧은 인용·URL·작가의 요약만 두는 것이 저작권상 위험이 낮은 위치다(법률 자문 아님).
- 화면에 자료를 보여 줄 때는 **출처를 항상 표시**한다.

## 자료를 집필에 쓰는 규칙

자료는 설정 본문과 같은 규칙으로 AI 컨텍스트에 들어간다([04 스토리 엔진의 컨텍스트 조립 규칙](04-story-engine.md#컨텍스트-조립-규칙)).

- 작가가 회차에 **고정**한 자료, 또는 **제목·태그가 현재 회차나 플롯 메모에 언급된** 자료만 넣는다.
- 넣는 것은 **제목과 요약뿐**이다. 인용문·URL·웹 원문은 넣지 않는다. 웹 원문을 집필 컨텍스트에서 빼면 웹 페이지에 숨은 프롬프트 인젝션도 함께 막힌다.
- 자료 몫에 **토큰 상한**을 둬서 직전 회차 전문을 밀어내지 않게 한다. 상한 값은 story가 정할 것이다.

자료가 조사 질문에서 집필 컨텍스트까지 가는 과정은 짧은 선형 흐름이다.

```
사이드 패널 질문 → web_search·web_fetch 답변(출처 포함) → 작가가 "자료로 저장" → 요약 검토 → 고정 또는 언급 시 제목·요약만 컨텍스트에 포함
```

## 역할별로 정할 것

- story: 검색 프롬프트, `max_uses`, 허용·차단 도메인 목록(차단 목록에 네이버 블로그·뉴스·지식백과 포함), 요약 초안 형식, 자료 토큰 상한.
- frontend: 자료 화면, "자료로 저장" 동작, 출처 표시 방식, 회차에 자료를 고정하는 방법.
- backend: 자료·출처 저장 스키마([03 데이터 모델의 자료](03-data-model.md#자료)).
