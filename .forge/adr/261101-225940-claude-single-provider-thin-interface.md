# 텍스트 LLM은 Claude 단일 공급자로, story-engine 내부의 얇은 인터페이스 뒤에 둔다

집필·ghost text·설정 점검 등 텍스트 생성은 Claude 하나로 시작하고(본 집필은 상위 모델, ghost text는 빠른 하위 모델), 공급자 SDK 호출은 story-engine 안의 얇은 내부 인터페이스(생성·스트리밍) 뒤에만 둔다. LiteLLM 같은 다중 공급자 추상화 계층은 쓰지 않는다. 공급자마다 프롬프트 캐싱·웹 검색 도구·구조화 출력 방식이 달라, 최소공통분모로 추상화하면 긴 설정 컨텍스트 캐싱처럼 일관성 유지에 필요한 기능을 쓰기 어려워지기 때문이다. 이미지 생성은 이와 별개로 다른 공급자를 쓴다.
