# 2026-11-05 — 이미지 일관성·검열 오탐 스파이크: Gemini 어댑터와 시험 장치 구축 (실제 실행은 생략)

## 계획과 실제
- 계획대로 된 것: S1 `direction` 필드, S2 Gemini 어댑터(`@google/genai@2.32.0`), S4 docs/05(통과 기준, 확인된 모델 ID·단가)를 계획대로 끝냈다. DoD 1~5는 오케스트레이터가 직접 다시 실행해 통과를 확인했다(테스트 14개, `pnpm -r typecheck`, check-ignore, 가짜 실행 16·30행, docs/05 grep).
- 달라진 것:
  - S3 시험 장치의 첫 구현에 결함이 있었고, 오케스트레이터 검토에서 찾았다. 안전 차단이 아닌 오류가 한 번만 나도 실행 전체가 멈췄고, 판정표는 마지막에만 저장했다. 실제 실행에서 오류가 한 번 나면 그때까지 비용을 낸 결과가 판정표에 남지 않는 구조였다. 수정 후에는 오류를 행으로 남기고, 호출마다 판정표를 저장하며, 이미지 없이 텍스트만 오는 응답을 `ImageNoImageError`로 구분한다.
  - 실행은 Dynamic Workflow 대신 팀 규칙에 따라 Paseo imagery 역할(codex)에 맡겼다. docs/05는 담당 역할이 없어 오케스트레이터가 직접 썼다.
  - 2026-11-03 무렵 `.git`이 원인 불명으로 사라져 푸시하지 않은 커밋 6개를 잃었다. 작업 트리는 남아 있어, 원격에서 `.git`만 다시 받아 붙이고 재커밋했다(슬라이스별 커밋은 하나로 합쳐짐).
  - UAT(실제 Gemini 실행 후 사람 판정)는 키와 입력 이미지가 준비되지 않아 사용자 결정으로 `skipped` 처리했다. 그래서 이 스파이크의 본래 질문인 "Gemini가 일관성·검열 기준을 통과하는가"에는 아직 답이 없다.

## 배운 것
- 다음에 다르게 할 것:
  - 비용이 드는 외부 API를 여러 번 순차 호출하는 시험 장치는 처음부터 **호출 단위로 오류를 기록하고 결과를 계속 저장**하도록 계획 DoD에 적는다. 이번에는 DoD가 "가짜 실행 성공"만 확인해서, 오류 경로가 실행 전체를 멈추는 결함을 DoD로는 잡지 못했다. `--fake-error`처럼 오류를 주입한 실행을 DoD 항목으로 둔다.
  - 사람이 준비해야 하는 전제(API 키, 입력 이미지)가 있는 스파이크는 그릴링 단계에서 **준비 시점을 확인하고**, 준비되지 않았으면 실행 전에 알린다. 이번에는 구현이 끝난 뒤 UAT 시도가 세 번 같은 이유로 막혔고, 결국 실제 결과 없이 봉인했다.
  - 다른 세션이 같은 작업 디렉터리를 쓰는 상황에서는 **브랜치를 원격에 자주 푸시**한다. 로컬 커밋만 있던 상태에서 `.git`이 사라지자 기록을 잃었다. 커밋은 경로를 지정해 하고(`git add -A` 금지), 남의 미커밋 변경과 섞지 않는다.
  - Gemini 이미지 모델은 무료 등급이 없다(2026-11-03 가격표). 구독제로는 시험할 수 없으므로 이미지 쪽 개발 시험에는 종량제 키가 필요하다.
