# M1 수락 기준 (AC) — qa가 쓰는 수락 테스트의 계약

이 목록은 M1 구현 루프의 멈춤 조건(K3)이다. qa는 `tests/`에 각 AC마다 테스트 이름에 `[AC-xx]` 태그를 붙인 테스트를 1개 이상 쓴다. 테스트는 **동작**을 확인해야 한다 — 상태 코드만 보지 말고, 응답 본문·DB 상태·부작용(파일·기록)까지 단언한다. 근거 문서는 `docs/`다.

실행 계약: `tests/package.json`에 `test:accept` 스크립트를 두고, 실행 시 아래 두 리포트를 새로 쓴다.
- `tests/.reports/vitest.json` — vitest `--reporter=json --outputFile=...` (API·엔진 수락 테스트)
- `tests/.reports/playwright.json` — Playwright JSON 리포터 (AC-16 브라우저 E2E)

외부 API 키 없이 동작해야 한다. AI 공급자는 엔진이 제공하는 가짜 공급자(fake provider)로 바꿔 끼운다.

| AC | 기준 | 근거 |
|---|---|---|
| AC-01 | 초대 코드가 없거나 무효이거나 이미 사용된 경우 가입이 거절된다. 유효한 코드로 가입하면 로그인할 수 있다. 같은 코드는 다시 쓸 수 없다. | docs/02-architecture.md 인증과 초대 |
| AC-02 | 관리자는 작가의 비밀번호를 재설정할 수 있고, 재설정 후 새 비밀번호로만 로그인된다. 일반 작가는 재설정할 수 없다. | docs/02-architecture.md 인증과 초대 |
| AC-03 | 작가 B는 작가 A의 작품·회차·설정·자료·이미지를 조회하거나 수정할 수 없다(각 자원 종류마다 확인). | docs/01-product.md, docs/02-architecture.md |
| AC-04 | 작품을 만들고·조회하고·고치고·지울 수 있고, 컨셉 5항목(장르·톤·서술 시점·타깃 독자·화풍 프리셋)이 저장·조회된다. | docs/03-data-model.md 작품과 컨셉 |
| AC-05 | 회차를 만들고·조회하고·고치고·지울 수 있고 회차 순서가 유지된다. 본문 블록 JSON을 저장하면 일반 텍스트와 Markdown 파생본도 저장된다. | docs/03-data-model.md 회차 본문 저장 |
| AC-06 | 회차 스냅샷을 만들고 목록을 볼 수 있으며, 특정 스냅샷으로 복원하면 본문이 그 시점과 같아진다. | docs/06-editor-and-ai-ux.md 회차 스냅샷과 복원 |
| AC-07 | 설정 4종(캐릭터·장소·소품·세계관)을 CRUD할 수 있다. 종류별로 정의되지 않은 필드는 거부된다. 캐릭터 상태는 생존·사망·행방불명만 허용된다. 소품 소유자는 같은 작품의 캐릭터만 지정할 수 있다. | docs/03-data-model.md 설정 종류와 고정 필드 |
| AC-08 | 시놉시스(작품마다 하나), 플롯 메모(회차마다 하나), 고정 설정(회차 ↔ 설정 연결)을 만들고 고칠 수 있다. | docs/03-data-model.md, docs/04-story-engine.md |
| AC-09 | 자료를 CRUD할 수 있다. 출처 인용이 150자를 넘으면 거부된다. 웹 원문을 담는 필드는 없다. | docs/07-research.md 자료 저장 규칙 |
| AC-10 | 컨텍스트 조립: 모든 설정의 정형 필드·컨셉·시놉시스는 항상 포함된다. 설정 본문은 현재 회차에 이름·별칭이 나오거나 고정 설정일 때만 포함된다. 플롯 메모는 그 회차 것만 포함된다. 직전 N개 회차는 전문, 그 이전은 회차 요약으로 포함된다. 사이드 패널 대화는 포함되지 않는다. 자료는 고정·언급 시 제목·요약만 포함된다. (각 규칙을 포함·제외 양쪽으로 확인) | docs/04-story-engine.md 컨텍스트 조립 규칙 |
| AC-11 | 상태가 사망·행방불명인 캐릭터의 이름이나 별칭이 AI 제안에 나오면 자동 경고가 붙고, 그렇지 않으면 붙지 않는다. 이 검사는 LLM을 호출하지 않는다(가짜 공급자 호출 0회). | docs/04-story-engine.md 설정 충돌 검사 |
| AC-12 | 대화형 텍스트 기능(예: 이어쓰기) 요청이 SSE로 가짜 공급자의 토큰을 순서대로 흘려보내고 정상 종료된다. | docs/02-architecture.md AI 작업 실행 방식 |
| AC-13 | 긴 작업은 작업 테이블에 등록되어 대기 → 실행중 → 완료로 전이된다. 공급자 오류 시 실패로 기록되고 재요청할 수 있다. api를 재시작해도 작업 기록이 남는다. | docs/02-architecture.md AI 작업 실행 방식 |
| AC-14 | 가짜 이미지 공급자로 이미지 생성 작업을 실행하면 파일이 저장소 인터페이스(로컬 디스크)에 저장되고 이미지 기록에 모델 ID가 남는다. 다른 작가는 그 이미지를 받을 수 없다. | docs/05-image-engine.md |
| AC-15 | 가짜 공급자 호출 1회마다 AI 사용 기록이 1건(작가·기능·모델·사용량·추정 비용) 남는다. | docs/03-data-model.md AI 사용 기록 |
| AC-16 | 브라우저 E2E: 초대 코드로 가입한 작가가 로그인 → 작품 목록 → 작품 생성 → 설정 화면에서 캐릭터 생성까지 완료하고, 새로고침 후에도 데이터가 보인다. | docs/06-editor-and-ai-ux.md 화면 구성 |
