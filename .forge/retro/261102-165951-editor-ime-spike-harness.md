# 2026-11-02 — 에디터 한국어 IME 스파이크 시험 페이지와 체크리스트 구축

## Plan vs actual
- 계획대로 된 것: apps/web에 dev 전용 `spike-ime.html`과 70칸 체크리스트를 만들었고, BlockNote 0.57.0과 Plate 53.5.2를 정확한 버전으로 고정했다. 운영 빌드에는 시험 코드가 섞이지 않았다(DoD 1~6을 오케스트레이터가 직접 재실행해 통과 확인). 재실행 1회 뒤 사람 확인에서 두 에디터 모두 한글 입력 정상.
- 달라진 것:
  - 1회차 사람 확인에서 Plate만 한글 입력이 밀렸다. 시험 페이지가 Copilot 제안, 로그 setState에 따른 에디터 재렌더, 직접 구현한 "/" 메뉴를 모두 켠 채로만 시험할 수 있어서 라이브러리 결함인지 시험 코드 결함인지 가를 수 없었다. "기본 모드(플러그인 없음)" 토글, 로그 store 분리와 렌더 카운터, 조합 중 제안 미발생으로 고친 뒤 통과했다. 원인은 우리 시험 코드 쪽이었다.
  - Plate의 공식 "/" UI는 레지스트리에서 복사하는 코드라 패키지로 설치되지 않아 직접 줄여 구현했다. 그래서 두 후보가 "/" 항목에서 같은 조건이 아니며, 체크리스트에 "직접 구현 결함 가능"으로 표시했다.
  - pnpm 엄격 모드 때문에 계획에 없던 직접 의존성 7종을 추가했다.

## Learnings
- 다음에 다르게 할 것:
  - 라이브러리를 비교하는 스파이크는 처음부터 **맨 라이브러리(대조군)와 우리 연동 코드를 켠 상태를 토글로 분리**해 설계한다. 연동 코드가 켜진 상태로만 시험하면, 실패했을 때 후보를 잘못 떨어뜨릴 수 있다. 이번에는 결정 규칙대로라면 Plate가 탈락할 뻔했다.
  - 시험용 관측 도구(이벤트 로그 등)는 시험 대상 컴포넌트를 다시 그리지 않게 React 상태 밖에 둔다. 조합 중 재렌더는 그 자체로 IME를 깨뜨릴 수 있다.
  - 커서 옆 제안 UI는 "조합 중 CSS 숨김"으로는 부족하고, 조합 중에는 **발생 자체를 막아야** 한다. docs/06:116의 "CSS로 숨기는 방식을 우선 검토"는 실제 에디터 구현에서 재검토가 필요하다.
  - 계획에 "기본 제공 기능 사용"이라고 적을 때는 그 기능이 패키지로 설치되는지(레지스트리 복사형이 아닌지) 그릴링 단계에서 확인한다.
  - 사람 확인 결과 "잘 된다"는 어느 브라우저, 어느 동작(조합 중 Enter 등)인지 함께 기록해야 판정 근거가 된다.
