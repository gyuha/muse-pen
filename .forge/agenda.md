# 아젠다 — AI 협업 웹소설 집필 플랫폼 MVP 첫 빌드 착수
started: 2026-11-01

## 목적지
작게 시작할 MVP의 범위·기술 스택·데이터 모델·AI 협업 방식이 정해져, 각 역할(frontend·backend·story·imagery·qa·deploy)에 첫 빌드 작업을 백로그 플랜으로 넘길 수 있는 상태.

## 결정됨
- "사람과 같이 쓴다"의 의미 — 작가 1명 + AI 협업. 여러 사람의 공동 집필은 MVP에서 하지 않는다. (2026-11-01)
- MVP 사용자 범위 — 초대받은 소수 작가. 각자 계정으로 자기 작품만 다루고, 가입은 초대·허용 목록으로 제한한다. (2026-11-01)
- MVP AI 기능 — 텍스트 집필 보조(이어쓰기·다시쓰기·문체 다듬기), 줄거리 구상·회차 초안, 이미지(캐릭터·배경·소품), 자료 조사(웹 검색) 모두 포함. (2026-11-01)
- 로그인 수단 — 이메일+비밀번호, 관리자 발급 초대 코드로 가입. 인증 라이브러리를 사용하고, MVP의 비밀번호 재설정은 관리자가 처리한다(메일 발송 없음). (2026-11-01)
- 설정 문서 형태 — 정형 핵심 필드 + 자유 본문(블록 에디터) 혼합. (2026-11-01) [ADR-261101-223930](adr/261101-223930-setting-structured-fields-plus-free-body.md)
- 설정 종류와 정형 필드 — 고정 4종(캐릭터·장소·소품·세계관)과 고정 필드. 컨셉(장르·톤·서술 시점·화풍 프리셋·타깃 독자)은 작품 속성. 작가 정의 종류·필드는 MVP에서 없음. (2026-11-01)
- 에디터 AI 협업 방식 — 선택 영역 메뉴, "/" 명령 블록 생성, 사이드 AI 패널, ghost text 자동 제안 모두 MVP에 포함. (2026-11-01)
- AI 수정 반영과 버전 히스토리 — AI 제안은 원문과 비교해 보여 주고 작가가 수락·거절·다시 생성. 수락 시점과 자동 저장 때 회차 스냅샷을 남기고 시점 복원만 제공(버전 diff 화면은 미룸). (2026-11-01)
- 설정 주입 방식 — 모든 설정의 정형 필드와 컨셉은 항상 넣고, 설정 본문은 현재 회차에 이름·별칭이 언급된 설정과 작가가 회차에 고정한 설정만 넣는다. 임베딩 의미 검색은 미룬다. (2026-11-01)
- 설정 충돌 검사 — AI 제안마다 정형 필드 기반 자동 경고(예: 사망·행방불명 캐릭터 등장, LLM 호출 없음) + 작가가 요청하는 LLM "설정 점검"(회차 모순과 필드·본문 불일치 탐지). (2026-11-01)
- ghost text 호출 — 입력이 멈추고 한글 조합이 끝난 뒤 자동 호출, 한 문장 이내, 빠르고 싼 별도 모델, 작가별 켜기·끄기. 지연 시간 등 수치는 빌드 단계에서 조정. (2026-11-01)
- 이전 회차 전달 — 직전 N화(기본 1~2화) 전문 + 그 이전은 회차 요약. 요약은 작가가 회차를 완료로 표시할 때 AI가 만들고 작가가 고칠 수 있다. N은 빌드 단계에서 조정. (2026-11-01)
- 설정 변화 반영 — 회차 완료 시 AI가 회차 요약과 함께 정형 필드 변경 후보를 AI 제안으로 내고 작가가 수락한다. 필드는 현재 값만 둔다(과거 회차 퇴고 때 잘못된 경고는 감수). (2026-11-01)
- 줄거리 구상 결과 — 작품 시놉시스(항상 컨텍스트에 포함)와 회차 플롯 메모(해당 회차에만 포함)에 둔다. 사이드 패널 대화는 저장만 하고 컨텍스트에 넣지 않으며, 확정 내용은 작가가 옮긴다. (2026-11-01)
- 텍스트 LLM 구성 — Claude 단일 공급자(본 집필 상위 모델, ghost text 하위 모델), story-engine 내부의 얇은 인터페이스 뒤에 둔다. 다중 공급자 추상화 계층은 쓰지 않는다. (2026-11-01) [ADR-261101-225940](adr/261101-225940-claude-single-provider-thin-interface.md)
- AI API 비용 부담 — 서비스 키로 운영자가 부담한다. 작가 개인 키(BYOK)는 두지 않는다. (2026-11-01)
- 작가별 AI 사용량 — 모든 AI 호출의 사용량(작가·기능·모델·토큰/장수·추정 비용)을 기록만 하고, 앱 안의 한도는 두지 않는다. 운영자가 기록을 보고 관리한다. (2026-11-01)
- 앱 구조와 언어 — TypeScript 모노레포(pnpm workspace), apps/web과 apps/api 분리, 엔진·공유 타입은 packages/*. (2026-11-01) [ADR-261101-230415](adr/261101-230415-typescript-monorepo-web-api-split.md)
- 프론트엔드 프레임워크 — Vite + React SPA(클라이언트 라우팅). (2026-11-01)
- 백엔드 프레임워크 — Hono(Node 런타임). zod 검증, SSE 스트리밍, RPC 클라이언트로 web과 타입 공유. (2026-11-01)
- DB 접근층 — Drizzle + 이식성 규칙(저장소 계층 경유, SQLite 전용 기능 금지, 문자열 ULID/UUID, 시간 형식 통일). (2026-11-01) [ADR-261101-231535](adr/261101-231535-drizzle-sqlite-with-portability-rules.md)
- 이미지 파일 저장소 — 저장소 인터페이스(저장·읽기·삭제·접근 URL) 뒤에 두고 첫 구현은 로컬 디스크. 이미지는 api가 작가 권한을 확인해 내려준다. 배포가 휘발성 디스크 환경이면 다시 연다. (2026-11-01)
- AI 작업 실행 — 대화형 텍스트(이어쓰기·다시쓰기·ghost text·사이드 패널·자료 조사)는 요청 안에서 SSE 스트리밍. 이미지 생성·회차 완료 처리처럼 긴 작업은 SQLite 작업 테이블 + api 프로세스 내 워커. Redis는 쓰지 않는다. (2026-11-01)
- 배포 형태 — 단일 VPS + Docker Compose(Caddy + api), SQLite·이미지는 호스트 볼륨. Litestream 지속 복제와 이미지 주기 동기화 백업을 MVP에 포함. api는 단일 인스턴스. 공급자 콘솔 월 지출 한도 설정은 운영 작업으로 deploy에 전달. (2026-11-01) [ADR-261101-232141](adr/261101-232141-single-vps-docker-compose-single-instance.md)
- 자료 조사 검색 백엔드 — Claude web_search + web_fetch를 story-engine의 얇은 인터페이스 뒤에 둔다. 빌드 전 한국어 조사 질문 20~30개로 Claude 검색과 Tavily를 비교 검증하고, 크게 뒤지면 인터페이스 뒤에서 Tavily로 교체. 네이버 블로그·뉴스·지식백과는 robots.txt가 AI 봇을 금지하므로 근거 출처로 쓰지 않는다. (2026-11-01)
- 자료 저장과 주입 — 작가가 저장할 때만 자료로 남긴다(제목·질문·작가 편집 가능 요약·출처[URL·제목·150자 이내 인용·조회 시각]·태그). 웹 원문은 저장하지 않고 출처는 항상 표시. 집필 컨텍스트에는 고정되었거나 제목·태그가 회차·플롯 메모에 언급된 자료의 제목·요약만, 토큰 상한 안에서 넣는다. (2026-11-01)
- 이미지 일관성 — 승인된 대표 이미지 + 화풍 프리셋(문구·화풍 레퍼런스)을 매 요청에 넣는 레퍼런스 조건부 생성. Gemini(초안 Nano Banana 2.1, 최종 Pro)를 image-engine 인터페이스 뒤에. 이미지마다 모델 ID 기록. 빌드 전 일관성·검열 오탐 검증, 미통과 시 FLUX로 교체. (2026-11-01) [ADR-261101-233441](adr/261101-233441-reference-conditioned-images-gemini.md)
- 에디터 라이브러리와 저장 포맷 — BlockNote·Plate 한국어 IME 스파이크로 결정(하나만 통과 시 그것, 둘 다 통과 시 Plate, 둘 다 실패 시 Lexical 검토). 저장 원본은 라이브러리 블록 JSON, 일반 텍스트·Markdown 파생 저장. ghost text는 조합 중 숨김, Pretendard 정적 빌드. 스파이크는 빌드 작업이므로 fg-ask로 백로그 플랜화. (2026-11-01) [ADR-261101-233610](adr/261101-233610-editor-ime-spike-gate-block-json.md)

## 아직 흐림
- 회차 시점별 설정 값(회귀·회상 장르에서 "몇 화 기준" 외형·상태) — MVP는 현재 값만 두기로 했다. 실제 작품에서 잘못된 경고가 얼마나 거슬리는지 보고 질문으로 다듬는다.
- 장면 삽화 — 캐릭터 + 배경 + 소품을 한 장면으로 합성하는 이미지. 개별 이미지 일관성 방식이 정해진 뒤에야 질문으로 다듬을 수 있다.
- 외부 연재 플랫폼용 내보내기 형식.
- 프롬프트 템플릿·출력 스키마 버전 관리의 구체 방식 — story 엔진 구조가 정해진 뒤.
- 장편 일관성을 어떻게 평가(eval)할지 — 설정 주입 방식이 정해진 뒤.
- 캐릭터별 LoRA — 호스팅 모델 은퇴로 그림체가 바뀌는 문제가 실제로 생기거나, 자주 쓰이는 캐릭터의 고정력이 부족할 때 질문으로 다듬는다.

## 범위 밖
- 결제·요금제 — MVP 첫 빌드 착수와 무관하다.
- 독자용 연재 공개·댓글·구독 — 목적지는 집필 도구다.
- DBMS 실제 이전 작업 — MVP에서는 이전 가능한 설계(DB 접근층 질문)만 결정하고, 이전 실행은 이후 일이다.
- 모바일 네이티브 앱 — 웹으로 시작한다.
- 여러 작가의 공동 집필·실시간 동시 편집(CRDT 등) — MVP는 작가 1명 + AI 협업으로 정했다.
